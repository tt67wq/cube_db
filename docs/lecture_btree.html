第一部分模块定位与 COW B-tree 骨架

src/btree.zig 是 cube_db 的索引核心——一个页号寻址、写时复制（Copy-On-Write, COW） 的 B+ 树。与 v1 相同算法，但节点寻址用 u32 页号、I/O 走 PageStore 抽象、固定页大小 （PAGE_SIZE = 4096），分支子指针为 u32。脏页收集到 caller 的 ArrayList(u32)， 由上层（db.zig 事务）统一回收或提交。

1.1 文件定位与依赖

//! btree.zig — 页号 COW B-tree（v2，page-based）
//! 与 v1 btree.zig 相同算法，但节点寻址用 u32 页号，I/O 走 PageStore，
//! 固定页大小，分支子指针为 u32。脏页收集到 caller 的 ArrayList。
const std = @import("std");
const f2 = @import("format.zig");
const ps = @import("page_store.zig");

const PageStore = ps.PageStore;

三个导入各司其职：std 是标准库（分配器、切片、ArrayList）；f2（format.zig） 提供页格式常量与页头/CRC 编解码——PAGE_SIZE、PAGE_HEADER_SIZE = 24、PageHeader、 verifyPageChecksum/computePageChecksum/setPageChecksum、 PAGE_TYPE_LEAF/BRANCH/OVERFLOW；ps（page_store.zig）提供 PageStore 多态接口（readPage/writePage/allocPage 等）。 btree.zig 只依赖这两个模块，不直接碰文件 I/O 或 mmap。

💡 说明 COW 含义：写入永不修改既有页——而是分配新页、拷贝旧页内容、在新页上改、 把新页号向上回报。旧页标记为 dirty 由 caller 回收。读者因此可零拷贝借用页缓冲：COW 保证被读的旧页 在其生命期内内容不变。这是 getBorrowed 零拷贝与并发安全的基础。

1.2 关键常量：容量上下限与节点种类

pub const NULL_ROOT: u32 = 0;
pub const LEAF_MAX_ENTRIES: usize = 32;
pub const LEAF_MIN_ENTRIES: usize = LEAF_MAX_ENTRIES / 2;
pub const BRANCH_MAX_CHILDREN: usize = 64;
pub const BRANCH_MIN_CHILDREN: usize = BRANCH_MAX_CHILDREN / 2;

const LEAF_KIND: u8 = 2;
const BRANCH_KIND: u8 = 1;
常量值含义
NULL_ROOT0空树哨兵。insert/get 见此值即知树未初始化，走首叶创建/返 null
LEAF_MAX_ENTRIES32单叶最多 entry 数，超限触发分裂。LEAF_MIN_ENTRIES = 16 为下限（预留借用/合并用，当前实现未做强收缩）
BRANCH_MAX_CHILDREN64单 branch 最多子指针数，超限分裂。BRANCH_MIN_CHILDREN = 32
LEAF_KIND / BRANCH_KIND2 / 1payload 首字节节点种类标记，读路径据此分流 leaf / branch
⚠️ 注意 容量选型：叶 32 entry、branch 64 children 是 4KB 页下的经验值—— 变长 key/value 的实际占用由 leafPayloadSize 动态算，LEAF_MAX_ENTRIES 只卡条数上限。 若单条 value 极大（> MAX_INLINE_VALUE），走溢出页，不影响条数计数。

1.3 核心数据类型与 COW 总体思路

pub const LeafEntry = struct {
    tombstone: bool,
    key: []const u8,
    value: []const u8,
};

pub const WriteResult = struct {
    new_root: u32,
    live_delta: i64,
    count_delta: i64,
};

pub fn cmpKey(a: []const u8, b: []const u8) std.math.Order {
    return std.mem.order(u8, a, b);
}

LeafEntry 是上层传入的逻辑 entry：tombstone 表删除标记（COW 不物理删，留墓碑）， key/value 为字节切片。WriteResult 是写操作的回报：新 root 页号、 本次活字节数变化（live_delta，用于 byte_size 统计）、条目数变化（count_delta）。 cmpKey 是纯字节字典序比较，全树统一用它。

COW 写入数据流（单条 insert）：

  1. insert 读 root payload 判 leaf/branch。
  2. 递归 insertIntoLeaf / insertIntoBranch：沿途把旧页加入 dirty。
  3. 到达目标叶：拷旧页到栈缓冲 → patch 新 entry → allocPage 新页 → writeNodePage 写入。
  4. 若叶条数超 LEAF_MAX_ENTRIES：分裂成左右两叶，返 split_key + split_right。
  5. 父 branch：若子未分裂，cowBranchNoSplit 仅拷页 + patch 4 字节子指针；若分裂，decode/encode 重排。
  6. root 分裂：建新 branch root，指向左右子树。
  7. 返回 WriteResult{ new_root, live_delta, count_delta }，caller 据此更新 meta。

1.4 页 I/O 辅助三件套

三个函数封装"页 → payload"与"payload → 页"的转换，是所有读写路径的入口：

/// 从页读节点 payload（借用页缓冲，不拷贝）
pub fn readNodePayload(store: PageStore, page_no: u32) ![]const u8 {
    const page = try store.readPage(page_no);
    const arr: *const [f2.PAGE_SIZE]u8 = @ptrCast(page.ptr);
    if (!f2.verifyPageChecksum(arr)) return error.CorruptCrc;
    return page[f2.PAGE_HEADER_SIZE .. f2.PAGE_SIZE - 4];
}

/// Fast read: skip CRC verification for hot read path.
/// COW guarantees pages are never modified while being read,
/// so CRC check is only needed on crash recovery / reopen.
pub fn readNodePayloadFast(store: PageStore, page_no: u32) ![]const u8 {
    const page = try store.readPage(page_no);
    return page[f2.PAGE_HEADER_SIZE .. f2.PAGE_SIZE - 4];
}

/// 写节点页（页头 + payload + CRC）
pub fn writeNodePage(store: PageStore, page_no: u32, page_type: u8, nkeys: u16, payload: []const u8) !void {
    const page = try store.writePage(page_no);
    const arr: *[f2.PAGE_SIZE]u8 = @ptrCast(page.ptr);
    const hdr = f2.PageHeader{
        .page_no = page_no,
        .page_type = page_type,
        .gen = 0,
        .nkeys = nkeys,
        .free_next = 0,
    };
    f2.encodePageHeader(page[0..f2.PAGE_HEADER_SIZE], &hdr);
    @memcpy(page[f2.PAGE_HEADER_SIZE ..][0..payload.len], payload);
    const remaining = f2.PAGE_SIZE - f2.PAGE_HEADER_SIZE - 4 - payload.len;
    if (remaining > 0) @memset(page[f2.PAGE_HEADER_SIZE + payload.len .. f2.PAGE_SIZE - 4], 0);
    f2.setPageChecksum(arr, f2.computePageChecksum(arr));
}

payload 区是 [PAGE_HEADER_SIZE .. PAGE_SIZE-4)——页头 24B 在前，页尾 4B CRC 在后， 中间 4096 - 24 - 4 = 4068 字节是节点 payload。readNodePayload 带 CRC 校验（用于 崩溃恢复/重开），readNodePayloadFast 跳过 CRC（COW 保证运行时页不被改写，热读路径免校验省 CPU）。

页头字段类型说明
page_nou32页号，little-endian（encodePageHeader 写法）
page_typeu8PAGE_TYPE_LEAF=3 / BRANCH=2 / OVERFLOW=4
genu64代际号，当前固定 0（预留）
nkeysu16节点 entry/child 数，little-endian
free_nextu32溢出页链下一页号（溢出页用）；普通节点为 0
✅ 提示 注意 payload 首字节即节点 kind：LEAF_KIND=2 / BRANCH_KIND=1 写在 payload[0]。读路径 payload[0] == LEAF_KIND 即可分流，无需读页头 page_type—— 这是 getBorrowed / findInBranchPayload 零解码分流的依据。

第一部分到此。下面进入节点编码：先 Leaf（含溢出页），再 Branch。

第二部分Leaf 节点编码与溢出页

Leaf 节点存储有序的 key-value entry。变长 value 可能超过单页内联上限，此时走溢出页链。 本部分精讲 LeafEntry / DecodedLeafEntry、溢出页机制、leafPayloadSize / encodeLeafPayload / decodeLeafPayload 的字节布局与端序约定。

2.1 LeafEntry 与内联上限

/// 最大内联值大小（留余量给页头和多个 entry）
pub const MAX_INLINE_VALUE: usize = 3800;

/// 溢出页最多可存 payload 字节数
const OVERFLOW_PAYLOAD: usize = f2.PAGE_SIZE - f2.PAGE_HEADER_SIZE - 4;

/// flags: 1 = 溢出页
const LEAF_FLAG_OVERFLOW: u8 = 1;

MAX_INLINE_VALUE = 3800 是内联阈值：value ≤ 3800 字节直接放 leaf payload，> 3800 走溢出页。 这个值给页头、entry 元数据（每条至少 10 字节开销）和多条 entry 留了余量，避免单条大 value 把叶撑爆。 OVERFLOW_PAYLOAD = 4068 是单个溢出页能存的数据字节（页头 24B + CRC 4B 之外全可用）。

pub const DecodedLeafEntry = struct {
    tombstone: bool,
    key: []const u8,
    value: []const u8,   // 内联：指向 payload 切片；溢出：4 字节页号
    flags: u8,
    vlen: u32,       // 原始 value 长度（溢出时 = 完整 value 字节数）
};

fn needsOverflow(entry: LeafEntry) bool {
    return entry.value.len > MAX_INLINE_VALUE;
}
⚠️ 注意 DecodedLeafEntry.value 的二义性：内联时 value 是 payload 内的字节切片； 溢出时 value 是 4 字节的页号字节（不是真实 value）。调用方必须再查 flags： 若 flags & LEAF_FLAG_OVERFLOW，要把这 4 字节读成 u32 页号再去溢出页链取真实值。 Leaf.fromPayload 和 findInLeaf 都做了这个分支。

2.2 溢出页链：写/读/回收

溢出页是一条由 free_next 串起来的单向链表。每个溢出页页头 page_type = PAGE_TYPE_OVERFLOW， payload 区存 value 的一个 chunk（最多 OVERFLOW_PAYLOAD 字节），free_next 指向下一页。

/// 写值到溢出页链，返首页号
/// ponytail: MVP 无 nkeys 更新，链靠 free_next
fn writeOverflowPages(store: PageStore, value: []const u8) !u32 {
    var remaining = value.len;
    var offset: usize = 0;
    var first_page: u32 = 0;
    var prev_page: u32 = 0;
    while (remaining > 0) {
        const page_no = try store.allocPage();
        const page = try store.writePage(page_no);
        const arr: *[f2.PAGE_SIZE]u8 = @ptrCast(page.ptr);
        const chunk = @min(remaining, OVERFLOW_PAYLOAD);
        // ... 填页头(PAGE_TYPE_OVERFLOW) + memcpy chunk + 清零余量 + CRC ...
        if (first_page == 0) {
            first_page = page_no;
        } else {
            // 链接前页 → 本页：回写 prev 的 free_next
            const prev = try store.writePage(prev_page);
            var prev_hdr = f2.decodePageHeader(prev[0..f2.PAGE_HEADER_SIZE]);
            prev_hdr.free_next = page_no;
            f2.encodePageHeader(prev[0..f2.PAGE_HEADER_SIZE], &prev_hdr);
            f2.setPageChecksum(prev_arr, f2.computePageChecksum(prev_arr));
        }
        prev_page = page_no;
        remaining -= chunk;
        offset += chunk;
    }
    return first_page;
}
value > 3800B → allocPage 首页 → 写 chunk1（≤4068B） → 有剩余? allocPage 次页 → 回写首页 free_next=次页 → ↻ 返首页号

readOverflowValue 沿 free_next 链逐页 readNodePayload（带 CRC）， 拼接成完整 value（调用方 free）。freeOverflowPages 遍历链把各页号加入 dirty 列表， 由 caller 回收——注意它 readPage 失败即 return（链断裂静默终止，避免崩溃）。

fn readOverflowValue(allocator: std.mem.Allocator, store: PageStore, first_page: u32, vlen: u32) ![]u8 {
    const result = try allocator.alloc(u8, vlen);
    var offset: usize = 0;
    var cur = first_page;
    while (cur != 0 and offset < vlen) {
        const payload = try readNodePayload(store, cur);
        const chunk = @min(vlen - offset, payload.len);
        @memcpy(result[offset..][0..chunk], payload[0..chunk]);
        offset += chunk;
        const page = try store.readPage(cur);
        const hdr = f2.decodePageHeader(page[0..f2.PAGE_HEADER_SIZE]);
        cur = hdr.free_next;
    }
    return result;
}
⚠️ 注意 链遍历用带 CRC 的 readNodePayload：溢出页链是跨页结构，任一页损坏都会导致 value 截断。读取走 readNodePayload（CRC 校验）而非 Fast 版，保证损坏可被 CorruptCrc 错误捕获。热路径 getBorrowed 对溢出值直接返 null，迫使调用方走 get 走这条安全路径。

2.3 leafPayloadSize：容量预估

pub fn leafPayloadSize(entries: []const LeafEntry) usize {
    var n: usize = 1 + 2;  // kind(1) + count(2)
    for (entries) |e| {
        // tombstone(1) + klen(4) + key + vlen(4) + flags(1) + value
        const value_sz = if (e.value.len > MAX_INLINE_VALUE) @as(usize, 4) else e.value.len;
        n += 1 + 4 + e.key.len + 4 + 1 + value_sz;
    }
    return n;
}

每条 entry 开销：tombstone(1) + klen(4) + key + vlen(4) + flags(1) + value = 10 字节元数据 + key + value。 溢出 entry 的 value 字段只占 4 字节（页号），不是完整 value。这个函数用于写前预估 payload 大小， 确保不超过 PAGE_SIZE - PAGE_HEADER_SIZE - 4 = 4068。

2.4 encodeLeafPayload：字节布局

pub fn encodeLeafPayload(buf: []u8, entries: []const LeafEntry, store: PageStore, dirty: *std.ArrayList(u32)) !usize {
    _ = dirty;
    var pos: usize = 0;
    buf[pos] = LEAF_KIND;            pos += 1;
    std.mem.writeInt(u16, buf[pos..][0..2], @intCast(entries.len), .big); pos += 2;
    for (entries) |e| {
        const is_ov = e.value.len > MAX_INLINE_VALUE;
        buf[pos] = if (e.tombstone) @as(u8, 1) else 0; pos += 1;
        std.mem.writeInt(u32, buf[pos..][0..4], @intCast(e.key.len), .big); pos += 4;
        @memcpy(buf[pos..][0..e.key.len], e.key); pos += e.key.len;
        std.mem.writeInt(u32, buf[pos..][0..4], @intCast(e.value.len), .big); pos += 4;
        if (is_ov) {
            buf[pos] = LEAF_FLAG_OVERFLOW; pos += 1;
            const ov_page = try writeOverflowPages(store, e.value);
            std.mem.writeInt(u32, buf[pos..][0..4], ov_page, .little);  // ← little!
            pos += 4;
        } else {
            buf[pos] = 0; pos += 1;
            @memcpy(buf[pos..][0..e.value.len], e.value); pos += e.value.len;
        }
    }
    return pos;
}
🔴 危险 端序不一致（关键陷阱）：leaf payload 里 count / klen / vlen 用 big-endian， 但 溢出页号用 little-endian！encodeLeafPayload 写页号用 .little， decodeLeafPayload / findInLeaf 读页号也用 .little。这与页头 （encodePageHeader 全 little）不同——leaf 内的长度字段是 big，唯页号字段是 little。 改代码时务必保持读写端序配对，否则页号错读导致整树错乱。

字节布局总览（单条 entry）：

┌──────┬───────┬──────┬───────┬─────┬───────┬───────┬───────────────┐
│ kind │ count │ tomb │ klen  │ key │ vlen  │ flags │ value         │
│  1B  │  2B   │  1B  │  4B   │ ..  │  4B   │  1B   │ 内联=VL / 溢出=4B页号│
│  BE? │  BE   │  -   │  BE   │ raw │  BE   │  -    │ 溢出=LE       │
└──────┴───────┴──────┴───────┴─────┴───────┴───────┴───────────────┘
kind=LEAF_KIND(2); BE=big-endian; LE=little-endian; raw=原始字节

2.5 decodeLeafPayload：防御性解码

pub fn decodeLeafPayload(payload: []const u8, entries_out: []DecodedLeafEntry) !void {
    if (payload.len < 3) return error.Truncated;
    if (payload[0] != LEAF_KIND) return error.CorruptCrc;
    const count = std.mem.readInt(u16, payload[1..3], .big);
    if (entries_out.len < count) return error.Truncated;
    var pos: usize = 3;
    for (payload, 0..) |_, i| {
        if (i >= count) break;
        if (pos + 1 + 4 > payload.len) return error.Truncated;
        // ... 逐字段读，每步都查 pos+x > payload.len ...
        if (flags & LEAF_FLAG_OVERFLOW != 0) {
            if (pos + 4 > payload.len) return error.Truncated;
            const ov_page = payload[pos..pos+4]; pos += 4;
            entries_out[i] = .{ ..., .value = ov_page, ... };
        } else {
            if (pos + vlen > payload.len) return error.Truncated;
            const value = payload[pos .. pos + vlen]; pos += vlen;
            entries_out[i] = .{ ..., .value = value, ... };
        }
    }
}

每个字段读取前都做 pos + N > payload.len 边界检查，越界返 error.Truncated。 kind 字节不匹配返 error.CorruptCrc（复用此错误名表"页内容非法"）。这种防御性解码确保 损坏页不会导致越界读——配合 readNodePayload 的 CRC 校验，构成两层防护。

✅ 提示 解码零拷贝：decodeLeafPayload 返回的 key/value 是 指向 payload 的切片，不分配堆。Leaf.fromPayload 才会 dupe 到堆—— 因为 fromPayload 的 leaf 要在 payload 生命期外存活。这种分层让纯解码可复用于只读扫描。

第二部分到此。下一部分讲 Branch 编码与 Leaf/Branch 的内存表示。

第三部分Branch 节点编码与内存表示

Branch 节点存 N-1 个 key 和 N 个 u32 子指针。子指针是页号，指向下层 branch 或 leaf。 本部分讲 branch 字节布局，以及 Leaf / Branch 结构体如何把 payload 转成可操作内存表示。

3.1 branchPayloadSize / encode / decode

pub fn branchPayloadSize(keys: []const []const u8, children: []const u32) usize {
    var n: usize = 1 + 2;  // kind + count
    for (keys) |k| n += 4 + k.len;
    n += 4 * children.len;
    return n;
}

pub fn encodeBranchPayload(buf: []u8, keys: []const []const u8, children: []const u32) usize {
    // assert children.len >= 2, keys.len == children.len - 1
    buf[pos] = BRANCH_KIND; pos += 1;
    std.mem.writeInt(u16, buf[pos..][0..2], @intCast(children.len), .big); pos += 2;
    for (keys) |k| {  // keys 区：klen(4,BE) + key
        std.mem.writeInt(u32, buf[pos..][0..4], @intCast(k.len), .big); pos += 4;
        @memcpy(buf[pos..][0..k.len], k); pos += k.len;
    }
    for (children) |c| {  // children 区：u32(4,BE) 连续
        std.mem.writeInt(u32, buf[pos..][0..4], c, .big); pos += 4;
    }
}

branch 布局：kind(1) + count(2,BE) 头，接着 keys 区（每个 klen(4,BE)+key）， 最后 children 区（count 个 u32 连续，big-endian）。注意 branch 的 children 全用 big-endian，与 leaf 的溢出页号 little-endian 不同——这是端序约定的又一处不一致，改代码须留意。

┌──────┬───────┬─────────────────────┬────────────────────┐
│ kind │ count │   keys 区           │  children 区       │
│  1B  │  2B   │ [klen(4,BE)+key]*   │ [u32(4,BE)]*count  │
└──────┴───────┴─────────────────────┴────────────────────┘
count = children 数 = keys 数 + 1
💡 说明 children 区连续的好处：children 是定长 u32 数组，连续存放。 findChildIdxAndOffset 算出 children 区起始字节偏移后，cowBranchNoSplit 可直接 pos + child_idx * 4 定位某子指针字节，patch 4 字节即完成 COW——无需 decode 整个 branch。

3.2 Leaf / Branch 内存表示与 fromPayload

Leaf / Branch 是堆拥有的内存表示：key/value/child 都 dupe 到堆， 脱离 payload 生命期。fromPayload 解码 + 堆拷贝，deinit 释放。

pub const Leaf = struct {
    entries: []LeafEntry,
    allocator: std.mem.Allocator,

    pub fn fromPayload(allocator, store, payload, dirty) !Leaf {
        // decode → 遍历 dec_slice
        for (dec_slice, 0..) |d, i| {
            if (d.flags & LEAF_FLAG_OVERFLOW != 0) {
                const ov_page = std.mem.readInt(u32, d.value[0..4], .little);
                freeOverflowPages(store, ov_page, dirty, allocator);  // 旧溢出页入 dirty
                const full_val = try readOverflowValue(allocator, store, ov_page, d.vlen);
                entries[i] = .{ .tombstone = d.tombstone, .key = try allocator.dupe(u8, d.key), .value = full_val };
            } else {
                entries[i] = .{ ..., .value = try allocator.dupe(u8, d.value) };
            }
        }
    }

    pub fn findPos(self, key) usize {  // 二分找插入位置
        var lo: usize = 0; var hi = self.entries.len;
        while (lo < hi) {
            const mid = lo + (hi - lo) / 2;
            switch (cmpKey(self.entries[mid].key, key)) {
                .lt => lo = mid + 1,
                .eq, .gt => hi = mid,
            }
        }
        return lo;
    }
};

pub const Branch = struct {
    keys: [][]u8,
    children: []u32,
    // fromPayload: decode → dupe keys → copy children
    pub fn findChild(self, key) usize {  // 找 key 应走哪个子
        // keys[mid] < key → 走右；keys[mid] >= key → 走左
    }
};
⚠️ 注意 fromPayload 的副作用——旧溢出页入 dirty：Leaf.fromPayload 在解码溢出 entry 时 会调 freeOverflowPages 把旧溢出页加入 dirty。因为 COW 写入会用新溢出页替换旧的， 旧链必须回收。insertIntoLeafSplit / insertBatchIntoLeaf 走此路径，caller 的 dirty 列表 负责最终 freePage。

第三部分到此。下一部分讲读取路径 get / getBorrowed。

第四部分读取路径：get / getBorrowed

读路径分两档：getBorrowed 零拷贝借用页缓冲（内联值热路径），get 堆拷贝（溢出值 / 需独立生命期）。 两者共享 findInBranchPayload 做原页二分下沉，区别只在叶层处理。

4.1 getBorrowed：零拷贝热路径

pub fn getBorrowed(store: PageStore, root: u32, key: []const u8) !?[]const u8 {
    if (root == NULL_ROOT) return null;
    var cur = root;
    var depth: u32 = 0;
    while (depth < 1000) : (depth += 1) {
        const payload = try readNodePayloadFast(store, cur);  // 跳 CRC
        if (payload[0] == LEAF_KIND) return findInLeafBorrowed(payload, key);
        else cur = try findInBranchPayload(payload, key);
    }
    return error.Truncated;
}

getBorrowed 从 root 下沉：branch 层调 findInBranchPayload 取下一层页号， 到 leaf 层调 findInLeafBorrowed。全程 readNodePayloadFast（跳 CRC，COW 保证安全）， 返回的切片直接指向页缓冲——零堆分配。depth < 1000 是防环保护。

root → readNodePayloadFast → payload[0]==LEAF? → 是 findInLeafBorrowed → 返借用切片 → 否 findInBranchPayload → cur=child → ↻ 
fn findInLeafBorrowed(payload, key) !?[]const u8 {
    // 逐条扫描，cmpKey 分流：
    .lt => { pos += value_sz; continue; }  // 跳过
    .eq => {
        if (tombstone) return null;       // 墓碑 = 不存在
        if (flags & LEAF_FLAG_OVERFLOW != 0) return null;  // 溢出 → 信号
        return payload[pos .. pos + vlen];   // ← 借用切片
    }
    .gt => return null;  // 越过插入点，key 不存在
}
🔴 危险 getBorrowed 对溢出值返 null：这是信号不是"不存在"。 findInLeafBorrowed 遇溢出 entry 无法返借用切片（值跨多页），返 null 让调用方改走 get。 调用方若不区分"墓碑 null / 越界 null / 溢出 null"，会误判溢出值为不存在。正确用法： getBorrowed 返 null 时若需确认，再调 get。

4.2 get 与 findInLeaf：溢出与 tombstone

pub fn get(allocator, store, root, key) !?[]u8 {
    // 同 getBorrowed 下沉，但叶层调 findInLeaf（堆拷贝）
}

fn findInLeaf(allocator, store, payload, key) !?[]u8 {
    .eq => {
        if (tombstone) return null;
        if (flags & LEAF_FLAG_OVERFLOW != 0) {
            const ov_page = std.mem.readInt(u32, payload[pos..][0..4], .little);
            return try readOverflowValue(allocator, store, ov_page, @intCast(vlen));
        }
        return try allocator.dupe(u8, payload[pos .. pos + vlen]);  // 堆拷贝
    }
}

get 是 getBorrowed 的"完整版"：内联值 allocator.dupe 堆拷贝， 溢出值 readOverflowValue 拼链。返回的 []u8 由调用方 free。 墓碑一律返 null——墓碑是 COW 删除留下的逻辑删除标记，读路径视为不存在。

4.3 findInBranchPayload：原页二分

fn findInBranchPayload(payload, key) !u32 {
    const count = std.mem.readInt(u16, payload[1..3], .big);
    var pos: usize = 3;
    var child_idx: usize = 0;
    var found = false;
    var i: usize = 0;
    while (i + 1 < count) : (i += 1) {
        // 读 klen + key，逐 key 比较
        if (!found and cmpKey(ek, key) == .gt) { child_idx = i; found = true; }
    }
    if (!found) child_idx = count - 1;  // key >= 所有 keys → 走最右子
    return std.mem.readInt(u32, payload[pos + child_idx * 4 ..][0..4], .big);
}

这是线性扫描找第一个 key > ek 的位置（虽名为二分下沉，实为顺序遍历 keys 区）。 keys 区扫完后 pos 落在 children 区起点，pos + child_idx*4 定位目标子指针。 越界检查 pos + 4*count > payload.len 防 Truncated。

💡 说明 getBorrowed 的生命期保证：返回的切片借自 readNodePayloadFast 的页缓冲。 COW 保证旧页不被改写（写者分配新页），因此切片在调用方使用期间有效——前提是底层 PageStore 实现保证页地址稳定（内存版每页独立堆分配，见 page_store.zig 讲义）。

第四部分到此。下一部分讲写路径——单条 insert 的 COW 实现。

第五部分插入（COW）：快路径与分裂

单条 insert 是 COW B-tree 的写路径核心。它分两层：叶层 insertIntoLeaf（快路径 patch / 慢路径分裂），branch 层 insertIntoBranch（递归 + cowBranchNoSplit 快路径 / decode-encode 慢路径）。 本部分逐个拆解。

5.1 insert 入口与 root 分裂

pub fn insert(allocator, store, root, key, value, tombstone, dirty) !WriteResult {
    if (root == NULL_ROOT) {
        // 空树：建首个 leaf，写一条 entry
        const new_page = try store.allocPage();
        // encodeLeafPayload + writeNodePage(LEAF)
        return .{ .new_root = new_page, ... };
    }
    const payload = try readNodePayload(store, root);
    const is_leaf = payload[0] == LEAF_KIND;
    const sub = if (is_leaf)
        try insertIntoLeaf(...)
    else
        try insertIntoBranch(...);

    if (sub.split_key) |sk| {
        // root 分裂：建新 branch root，指向 sub.new_child 与 sub.split_right
        var keys = .{sk};
        var children = .{ sub.new_child, sub.split_right };
        // allocPage + encodeBranchPayload + writeNodePage(BRANCH)
        return .{ .new_root = new_page, ... };
    }
    return .{ .new_root = sub.new_child, ... };
}

insert 读 root payload 判 leaf/branch，调对应插入函数。InsertSub 结构体是子层回报： new_child（新页号）、可选 split_key + split_right（分裂时）、live_delta / count_delta。root 分裂时建新 branch root——这是树长高的唯一时机。

const InsertSub = struct {
    new_child: u32,
    split_key: ?[]u8 = null,
    split_right: u32 = 0,
    live_delta: i64 = 0,
    count_delta: i64 = 0,
};

5.2 insertIntoLeaf：栈缓冲 patch

insertIntoLeaf 是叶层 COW 核心。它分两条路：快路径（条数未超限，栈缓冲 patch 新 entry） 和慢路径（超限，调 insertIntoLeafSplit decode/分裂/encode）。

fn insertIntoLeaf(store, allocator, page_no, key, value, tombstone, dirty) !InsertSub {
    // ① 拷旧页到栈缓冲 — allocPage 可能触发 HashMap resize 使 readPage 切片失效
    const old_page = try store.readPage(page_no);
    var old_page_buf: [f2.PAGE_SIZE]u8 = undefined;
    @memcpy(&old_page_buf, old_page[0..f2.PAGE_SIZE]);
    const old_payload = old_page_buf[f2.PAGE_HEADER_SIZE .. f2.PAGE_SIZE - 4];

    // ② 扫描 old_payload 找插入位置 + 记录 entry_start/entry_end/entries_end
    //    同时记录 old entry 元信息（tombstone/vlen/is_overflow/overflow_page）
    // ③ 算 live_delta / count_delta（覆盖时减旧、加新）
    // ④ 若旧 entry 是溢出，freeOverflowPages 旧链入 dirty

    const new_count: u16 = if (found) old_count else old_count + 1;
    dirty.append(allocator, page_no) catch {};  // 旧页入 dirty

    if (new_count > LEAF_MAX_ENTRIES) {
        return insertIntoLeafSplit(store, allocator, old_page_buf[0..], ...);
    }

    // ⑤ 快路径：栈缓冲拼新 payload（header + before + 新 entry + after）
    var new_payload: [f2.PAGE_SIZE - f2.PAGE_HEADER_SIZE - 4]u8 = undefined;
    // ⑥ allocPage + writeNodePage(LEAF) 写入
    return .{ .new_child = new_page, .live_delta, .count_delta };
}
🔴 危险 栈缓冲拷贝的关键理由：注释明确——allocPage 可能触发底层 HashMap resize，使此前 readPage 返回的借用切片悬垂。因此必须先把整页 @memcpy 到栈 old_page_buf，后续所有扫描/拷贝都基于栈缓冲，allocPage 之后才安全。 cowBranchNoSplit 同此模式。这是 COW 写路径的不变量：用旧页数据前先拷离页缓冲。
⚠️ 注意 live_delta 计算：覆盖时减去旧 entry 大小 old_key_len + old_val_sz + 9 （9 = 1 tombstone + 4 klen + 4 vlen；注意 flags 1 字节已计入 9？实际公式 key.len + value.len + 9， 9 含 tombstone/klen/vlen/flags 共 10？源码写作 +9，遵循源码）。新增则只加 key.len + value.len + 9。 tombstone 的 value 按 0 长度计。count_delta：活→墓 -1，墓→活 +1，新增活 +1。

慢路径 insertIntoLeafSplit：decode 旧叶为内存 Leaf → 应用 insert/overwrite → 对半分裂成左右两叶 → encodeLeafPayload + writeNodePage 各写一页 → 返 split_key = right_entries[0].key。

5.3 cowBranchNoSplit：4 字节 patch

fn cowBranchNoSplit(store, old_page_no, child_idx, children_offset, new_child) !u32 {
    // 拷旧页到栈（防 allocPage resize 悬垂）
    const old_page = try store.readPage(old_page_no);
    var page_copy: [f2.PAGE_SIZE]u8 = undefined;
    @memcpy(&page_copy, old_page[0..f2.PAGE_SIZE]);

    const new_page_no = try store.allocPage();
    const new_page = try store.writePage(new_page_no);
    @memcpy(new_page[0..f2.PAGE_SIZE], &page_copy);  // 整页拷

    std.mem.writeInt(u32, new_page[0..4], new_page_no, .little);  // 改页头 page_no
    // patch 子指针（big-endian）
    const off = f2.PAGE_HEADER_SIZE + children_offset + child_idx * 4;
    std.mem.writeInt(u32, new_page[off..][0..4], new_child, .big);
    f2.setPageChecksum(arr, f2.computePageChecksum(arr));
    return new_page_no;
}

这是 branch 快路径：子未分裂时，无需 decode/encode 整个 branch——整页拷贝 + 改页头 page_no + patch 4 字节子指针 + 重算 CRC。零堆分配。findChildIdxAndOffset 预先算出 child_idx 和 children_offset（children 区起始偏移），cowBranchNoSplit 直接用。

5.4 insertIntoBranch：递归 + 快/慢路径

fn insertIntoBranch(store, allocator, page_no, key, value, tombstone, dirty) !InsertSub {
    const payload = try readNodePayload(store, page_no);
    const loc = try findChildIdxAndOffset(payload, key);  // 找子 + offset

    // 判子是 leaf/branch，递归插入
    const child_is_leaf = ...;
    const sub = if (child_is_leaf)
        try insertIntoLeaf(store, allocator, loc.child, ...)
    else
        try insertIntoBranch(store, allocator, loc.child, ...);

    dirty.append(allocator, page_no) catch {};

    if (sub.split_key == null) {
        // ① 快路径：子未分裂 → cowBranchNoSplit
        const new_page = try cowBranchNoSplit(store, page_no, loc.idx, loc.children_offset, sub.new_child);
        return .{ .new_child = new_page, ... };
    }

    // ② 慢路径：子分裂 → 重读 payload（递归可能 allocPage 使旧 payload 失效）
    const fresh_payload = try readNodePayload(store, page_no);
    var branch = try Branch.fromPayload(allocator, fresh_payload);
    defer branch.deinit();
    // 替换 child[ci] = new_child，插入 split_key + split_right at ci
    // 若超 BRANCH_MAX_CHILDREN → 分裂 branch，返 up_key + right_page
}
⚠️ 注意 慢路径重读 payload：注释明说"recursive insert may have allocated pages, invalidating the earlier borrowed slice"。慢路径不复用开头读的 payload，而是 readNodePayload 重读一份再 decode。这与快路径 cowBranchNoSplit 的栈拷贝是同一问题的两种应对： 快路径在 allocPage 前就拷走整页，慢路径在 allocPage 后重读。

branch 分裂：取 mid = keys.len/2，up_key = keys[mid] 上提，左右两半各成一页。 up_key 是右子最小 key，上提到父节点作分隔键。

第五部分到此。下一部分讲批量插入与整体设计取舍。

第六部分批量插入与设计取舍

批量插入 insertBatch 接受已排序的 entry 列表，沿 B-tree 路径一次遍历， 同一叶范围内的 entry 只复制一次页。这是单条 insert 的"向量化"优化。

6.1 insertBatch 路由

pub fn insertBatch(allocator, store, root, entries, dirty) !WriteResult {
    if (entries.len == 0) return .{ .new_root = root, ... };
    if (root == NULL_ROOT) return insertBatchFresh(allocator, store, entries, dirty);

    const payload = try readNodePayloadFast(store, root);
    const is_leaf = payload[0] == LEAF_KIND;
    const sub = if (is_leaf)
        try insertBatchIntoLeaf(...)
    else
        try insertBatchIntoBranch(...);

    if (sub.split_key) |sk| { /* 建 new root branch */ }
    return .{ .new_root = sub.new_child, ... };
}

三条路径：insertBatchFresh（空树）、insertBatchIntoLeaf（root 是叶）、 insertBatchIntoBranch（root 是 branch）。root 分裂逻辑与单条 insert 相同。

6.2 insertBatchIntoLeaf：O(n+m) 归并

fn insertBatchIntoLeaf(store, allocator, page_no, entries, dirty) !InsertSub {
    // 拷旧页 → Leaf.fromPayload（旧溢出页入 dirty）

                     oi += 1; bi += 1; }
        }
    }
    // 收尾：剩余旧 / 剩余新

    if (merged_entries.len <= LEAF_MAX_ENTRIES) {
        // 单叶容纳：encodeLeafPayload + writeNodePage
    } else {
        // 多叶：chunk 成 LEAF_MAX_ENTRIES 一组，建叶页 + branch 树

✅ 提示 O(n+m) 归并：旧叶条目与批量条目都已排序，双游标归并一遍即可产出合并结果。 同 key 取批量条目（last-write-wins）——这是批量插入的语义约定，调用方须保证 entries 已按 key 升序排好。
🔴 危险 覆盖时防 deinit 双释放：eq 分支释放旧 entry 的 key/value 后， leaf.deinit 会再次 free 同一指针 → double-free。解法：释放后把 leaf.entries[oi] 替换成空切片 &[_]u8{}，让 deinit 释放空切片（no-op）。 这是所有权管理的精细点——Leaf 拥有 entries 内存，归并时转移所有权须同步置空旧引用。

批量条目超单叶容量时，走 insertBatchSplitLeaves / insertBatchFresh 的 bulk-load： 按 LEAF_MAX_ENTRIES 切块建叶页，再用 BRANCH_MAX_CHILDREN 切块逐层建 branch。

6.4 设计要点与风险清单

设计要点：

  • COW 保证借用生命期：写者永不改既有页，读者零拷贝借页缓冲。写路径用栈拷贝规避 allocPage 触发的 HashMap resize 悬垂。
  • 脏页外挂 caller：写路径不直接 freePage，旧页号收集到 caller 的 ArrayList(u32)，由事务层统一回收。解耦写入与回收。
  • 快/慢路径分层：叶层 patch vs 分裂；branch 层 cowBranchNoSplit 4 字节 patch vs decode-encode。常见无分裂情形走快路径零堆分配。
  • 溢出页链：大 value 走 free_next 单向链，叶内只存 4 字节首页号。读时拼链，覆盖时旧链入 dirty。
  • 批量归并 O(n+m)：已排序批量与已排序叶条目双游标归并，last-write-wins，避免逐条 COW 重复拷页。
  • 防御性越界检查：每个 decode 步骤 pos + N > payload.len 查 Truncated，kind 字节查 CorruptCrc，@min(count, ...) 卡上限。
