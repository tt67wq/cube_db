# cube_db benchmark 数据 — 2026-09-08

机器: Apple M1 Pro / 8 cores / macOS
构建: `zig build bench -Doptimize=ReleaseFast -Dbench-scale=small`
Zig: 0.16.0
工作负载: 顺序 put + 随机 get/批量提交，**no fsync**（MemPageStore 纯内存后端）。
测试时架构状态: HEAD `a3283b2`（T-34 全流程之后）— 纯 COW B-tree + freelist 持久化 + 显式 Reader/WriteTxn API + 有序 fast path + CRC 硬件加速。

> 自上次全矩阵（`20260730_bench.md`）以来完成 T-27~T-34 多条优化线（zero-copy get、COW 优化、Shared COW、CRC 跳过、有序 fast path、freelist 持久化、多进程 flock 防护），本表即当前 HEAD 的完整可复现基线。

## 读延迟（get，随机 key）

| value | avg_us/op | ops/s |
|---|---:|---:|
| 100B | 4.70 | 212838 |
| 10KB | 4.36 | 229600 |

> get 100B 从 2026-07-30 的 35.53µs → **4.70µs（7.6×）**。CRC 跳过 + zero-copy 读路径 + 有序 fast path 的累积效果。10KB 反略低于 100B，因随机 key 命中路径长度抖动，量级一致。
